Recommended v1

One manager thinks. Small models build.

A lightweight command layer for autonomous work across repos.

The user talks to one high-capability Claude or Codex manager. It delegates bounded repository work to the smallest eligible worker profile, resolves routine uncertainty, aligns cross-repo changes, personally reviews the exact final diff, and opens the PR.

What changes from Firstmate

Keep the command philosophy. Remove the fleet machinery.

Firstmate proves the value of a single liaison, worktree isolation, explicit authority, event-driven supervision, and restart-proof records. Papaya Agent Runtime narrows the surface to the exact workflow requested.

Routing policy

Choose the smallest profile likely to finish—not the cheapest call.

A failed tiny model can cost more than a correctly chosen small model. The manager routes by expected total cost and escalates only on evidence.

Agent communication

Structured subprocesses underneath; no terminal multiplexer in the protocol.

Firstmate benefits from tmux for a broad fleet of interactive agents. Papaya Agent Runtime can exploit Claude and Codex's non-interactive event streams and exact resume IDs, removing an entire layer of terminal state.

Normal path

One blocking wait

The manager dispatches, then waits on the supervisor. A question or completion wakes the same turn without periodic model calls.

Steering

Checkpoint or interrupt

Queue guidance for the next safe boundary, or interrupt urgently, reconcile the worktree, and resume the proven-compatible session.

Recovery

Runners guard live pipes

If the manager or supervisor disconnects, task runners continue spooling sequenced events. Reconnection replays only what was not acknowledged.

Optional

Tmux for eyes, not truth

A later observer may arrange logs and worktrees into panes. It never carries messages, identity, or lifecycle state.

Fail closed on continuity: if a provider/version cannot prove interrupted-session resume, Papaya Agent Runtime starts a fresh worker with the task packet, worktree diff, last checkpoint, and open obligations. It never claims seamless continuation based on a PID alone.

Worker uncertainty

Questions stop at the manager unless only the user can answer.

Resolve

Known, still-valid decision

Reuse a scoped prior answer only when its assumptions and context fingerprint still hold. Cite it and resume the same worker session.

Assume

Reversible uncertainty

Choose a sensible in-scope default, record the assumption, and keep moving.

Escalate

Critical decision

Ask the user for product direction, new authority, credentials, destructive action, conflicting requirements, or a ceiling increase.

When a worker is confused because the task is too broad, that is a routing problem. The manager splits or re-routes it instead of forwarding the confusion to the user.

Remember

Narrowest justified scope

Global, repo, product area, run, or task. A one-off answer never silently becomes a permanent preference.

Revalidate

Context fingerprint

Requirements, dependent decisions, relevant file/contract SHAs, authority, model ceilings, and time-sensitive facts.

Re-ask well

Ask only about the delta

Explain what changed, retain the old rationale, and link the replacement rather than relitigating the full question.

Lavish document loop

Complex work gets a review surface that talks back.

For architecture, plans, comparisons, release reviews, and connected decisions, the manager creates a portable HTML artifact. Comments inside that document are first-class user input, not a side channel the system forgets.

Create

Use when visual structure helps

Plans, diagrams, comparisons, reports, complex decisions. Skip trivial statuses and one-line questions.

Listen

Attached poll only

Foreground or supervisor-owned with a verified wake path. Never detached fire-and-forget.

Normalize

Load the small facts first

Persist prompts and summaries; fetch large snapshots, attachments, or whiteboard files only when needed.

Close

Respect Send & End

Consume final feedback once. Do not reopen a user-ended review without a new request.

Durable outcome: every applied comment links the artifact revision, feedback event, resulting decision or task change, and manager reply. A restart can reconstruct what was requested and what happened next.

Autonomous lifecycle

A run is a recoverable state machine, not a long chat.

stateDiagram-v2 [*] --> Requested Requested --> Planned Planned --> Ready Ready --> Running Running --> BlockedManager: worker question BlockedManager --> Running: manager answers BlockedManager --> BlockedUser: critical only BlockedUser --> Running: user decides Running --> WorkerDone WorkerDone --> ManagerReview ManagerReview --> Rework: changes required Rework --> Running ManagerReview --> Approved: exact HEAD passes Approved --> PROpen PROpen --> Complete Complete --> [*]

Manager acts without asking

  • Clone/fetch and create worktrees
  • Plan and align cross-repo work
  • Route, retry, split, and rework below ceilings
  • Run validations and make reversible assumptions
  • Commit, push, and open an approved PR

User remains the authority

  • Product or direction ambiguity
  • Scope expansion or conflicting requirements
  • Secrets, access, destructive or production actions
  • Worker ceiling or spend increases
  • Merging, unless explicitly granted later

Delivery gate

The manager reviews the exact commit that will be pushed.

🔐

Approval is SHA-bound

The review records its base and head. Any later commit invalidates approval. The PR command refuses to run until the new head is reviewed.

Review bundle

✓ Objective + acceptance criteria
✓ Base/head SHAs
✓ Diff summary + full diff path
✓ Test and validation evidence
✓ Assumptions + open questions
✓ Cross-repo contracts + rollout order
✓ Risks and dependency state
✓ Provider/model/usage ledger

A cheap reviewer may add evidence. Only the configured manager can issue the final approval.

Durable knowledge

Scoped memory, with provenance and a delete button.

Learning means preserving explicit, context-aware decisions and verified facts—not silently inferring a personality from chat or turning a one-off answer into permanent policy. Users can inspect, supersede, review, and forget every durable record.

Risks to design around

The sharp edges are knowable.

CLI drift

Flags and events change

Version probes, pinned companion tools, adapter fixtures, and fail-closed capability checks.

False cheapness

Tiny model, many retries

Route by expected total cost and use evidence-based escalation.

Continuity

Connections or sessions stop

Runner spools and disk state are authoritative; sockets and hooks are reconnectable wake paths.

Runaway autonomy

Prompt rules get ignored

Authority, ceilings, retries, and review gates live in runtime code.

Stale memory

Old facts steer new work

Scope, provenance, SHA validity, and explicit archive/forget flows.

Supply chain

Managed tools are executable

Pinned sources, checksums, MIT notices, isolated installs, explicit updates.
